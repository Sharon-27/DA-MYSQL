Transaction
-------------
The process of combining all related operations into a single unit and executing
then according to the rule "either all operations should succeed or none should succeed"
is called transaction management.
A transaction is considered a single unit of work and follows the principle "either all 
or none";

Example: Funds Transfer
Consider a money transfer process between two accounts:
Debit amount from the sender's account
Credit amount into the receiver's account
Both operations should be executed as a single transaction.
If the amount is debited from the sender's account successfully, but crediting
the receiver's account fails, it may lead to data inconsistency problems.

There are two types of transactions:
1. Local transactions
2. Global transactions

1. Local Transaction:
----------------------
In local transactions all operations of a transaction are executed on the same
database.
Example:
Funds transfer from one account to another account where both accounts belongs to
the same bank.

2. Global Transaction:
-----------------------
In global transactions all operations of a transaction are executed on the different
databases.
Example:
Funds transfer from one account to another account where both accounts belong to the
different banks.

ACID Properties:
------------------
Atomicity: all or nothing.
Consistency: the database remains in a valid state.
Isolation: transactions do not interface with each other.
Durability: committed changes are permanent.


TCL(Transaction Control Language):
------------------------------------
1. Commit
------------
Commit is used to permanently save all changes made during the current transaction into 
the database.

Once committed:
  changes become permanent.
  others users can see the changes.
  you cannot undo the changes using rollback.


2. Rollback:
-------------
Rollback is used to undo all changes made in the current transaction before a commit.
If something goes wrong. Rollback restores the database to its previous state.

INTRODUCTION TO STORED PROCEDURES:
=====================================
A stored procedure is a named, precompiled collection of one or more sql statements
that is stored inside the database and can be executed called whenever required. 
Instead of sending long block of sql from an application every time, the application
simply calls the procedure by name.

Why use stored procedures?
-----------------------------
1. Performance
2. Reusability
3. Security
4. Reduced Network Traffic
5. Maintainability
6. Consistency

ADVANTANGES:
---------------
Faster execution after completion.
Reduced duplicate sql.
Supports transaction, loops, conditions, variables...etc.
Easy Maintenance.

DISADVANTAGES:
---------------
Debugging can be difficult.
Vendor specific syntax.
Complex procedures may become hard to maintain.

Syntax to create stored procedures
--------------------------------------
DELIMITER //
CREATE PROCEDURE procedure_name()
BEGIN
 ---- sql statements
END //
DELIMITER ;

IN Parameter
-------------
An In Parameter is used to pass a value into a stored procedure.
The procedure can use the value, but changes made to the parameter inside the procedure
are not returned to the caller.

Syntax:
--------
DELIMITER //
CREATE PROCEDURE procedure_name(IN parameter_name datatype)
BEGIN
    sql statements;
END ;
DELIMITER ;

OUT PARAMETER:
----------------
An out parameter is used to return a value from the stores procedure to the caller.
The caller provides a variable to receive the result.

Syntax:
--------
DELIMITER //
create procedure procedure_name(OUT parameter_name datatype)
BEGIN
    SET parameter_name=value;
END;
